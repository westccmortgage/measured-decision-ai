Security you can read, not a badge you have to trust.

Measured Decision holds other people's construction records: plans, site captures, delivery paperwork, decisions. This page describes plainly how that record is protected — what is enforced in the database, what leaves the platform and when, and what we deliberately do not claim.

Four boundaries, enforced in the database

Every row knows its owner.

Row-level security is enabled on every table. An organization reads only its own projects; a query from anyone else returns nothing — not an error page, an empty answer. These rules live in the database itself, beneath the application, so no interface bug can widen them.

An external owner gets one door.

A project owner is invited by email and signs in with an emailed link — no password, no access token in a URL. The grant is read-only, scoped to that one project, expirable, and revocable by the project team at any moment. It opens the published record only: approved releases and published technical results, never drafts or working state.

Originals are never altered.

Uploaded evidence is preserved as captured, with its checksum recorded. Analysis, annotation and review happen beside the original, never inside it. Deletions are soft and audited; the decision log is append-only — who did what, and when, cannot be quietly rewritten.

AI output is labeled, not laundered.

Every machine reading in the product carries "Read by AI · not confirmed" until a named person signs it, line by line. Integrity of meaning is a security property here: nothing the software computed can silently become something a human attested.

How data moves

  1. Sign-in.Accounts are held by Supabase Auth over TLS. Project teams use passwords, magic links, or Google sign-in; invited owners use emailed magic links only. Sessions are stored by the browser client — never in page URLs.
  2. Every read and write passes row-level security.The application never trusts itself: the database checks organization membership or a project-scoped grant on each query. Signed-out callers cannot execute any function that acts on the record at all — permission is denied at the gate, not merely refused inside.
  3. Files live in private storage.Evidence and plans are stored in private buckets (AWS S3 and Supabase Storage), encrypted at rest by those platforms and reached only through URLs signed for a single hour. There are no public file links; an expired link is a dead link.
  4. AI processing is server-side and scoped.Plan and document readings run in server-side workers holding server-side keys — no AI provider credentials ever reach the browser. Content sent for analysis goes to the provider's API, whose terms exclude training on API inputs; where the processing mode allows it, we disable storage on the request itself.
  5. Everything consequential is audited.Approvals, releases, invitations, revocations, deletions — each writes an append-only audit event naming the actor, the object and the time.

Tested like a claim, not like a hope

The access rules above are asserted by an automated suite of over two hundred database invariants, run against a real PostgreSQL on every change: that another organization reads nothing, that a signed-out caller executes nothing, that an invited owner sees one project and cannot touch a second, that a revoked or expired key stops working, that the audit log cannot be edited. A rule that is not tested is a rule that can be removed by accident; these cannot be removed silently.

What we do not claim

We hold no SOC 2, ISO 27001, or other security certification, and we will not imply one with a badge. What you see on this page is what exists — practices we can demonstrate, enforced where they can be verified.

We do not claim your data never leaves the platform: plan and document content is processed by a third-party AI provider as described above, and files are stored on AWS and Supabase infrastructure.

We do not claim perfection. If you believe you have found a vulnerability, write to us and we will respond, take it seriously, and tell you what we did.
